## Added after handoff — Windows USB serial bridge (2026-10-09)

- `windows-app/AIClockBridge/SerialLink.cs` + `SerialProtocol.cs`: finds CH340/CH341/CH9102/CP210x COM ports via WMI (non-USB ports such as built-in COM1 are skipped; all ports are tried if WMI fails), handshakes `#HELLO` → `#DEVICE`, then pushes one frame per 250 ms tick: `#STATUS` 5 s, `#NET` 2 s, `#PC` 1 s, `#WEATHER`/`#TIME` 60 s. Frames over 1500 bytes are dropped (firmware line buffer is 1600);
- Display mode, brightness and horizontal mirror go over `#CMD` first whenever USB is linked, otherwise HTTP. The tray and mirror window show `USB 有线 COMx · 固件 x.y.z` when only the wired link is reachable. Mirror (sprite pull), Petdex upload and `/api/info` still need Wi-Fi.
- Firmware: new `#TIME {"epoch":N}` sets the clock (POSIX TZ `CLOCK_TIMEZONE`) only while SNTP is not running/valid, so a wired-only clock no longer stays on `WAITING FOR NTP`. New `#WEATHER {json}` feeds the same parser as HTTP `/weather`; HTTP weather polling pauses while serial weather is fresh (20 min).
- Windows holds COM ports exclusively: **quit AIClockBridge before flashing** with PlatformIO.
- Tests: `windows-app/Serial.Tests` (44 assertions, runs on any OS, added to CI). ESP8266 build: RAM 57.5%, flash 83.0%.
- Hardware checks to add to item 1 below: plug in USB with Wi-Fi off → clock shows Taipei time and weather within ~1 min; tray mode/brightness/mirror switch over USB; unplug/replug reconnects; flashing works after quitting the bridge.
